01

System block diagram

The video and audio paths are hardware data paths. Firmware configures them through XDATA peripheral registers and SFRs; the 8051 is shown as the control plane rather than a per-pixel software processor.

Video

HDMI reception feeds a processing path with procamp and timing configuration, then USB UVC capture. Upstream research describes YUV422 and MJPEG. Neutral FE90–FE93 values are verified; scaler and sharpening bypass controls remain unresolved.

Audio and control

HDMI audio extraction feeds PCM handling and USB UAC. The factory HID interface gives tools access to XDATA, SFR and EEPROM operations. Host format descriptors live in RAM; descriptor changes do not remove the initial extra sample word.

02

Firmware architecture

Mask ROM supplies boot and shared services. EEPROM code supplies hooks and variant-specific behavior in the RAM-backed CODE/XDATA overlay. The local patch extends the existing normal hook while preserving the original firmware body.

Normal entry and stage dispatch

The entry at CC00 receives the command in R7. On this device its original first instruction was MOV DPTR,#DE0B. The patch replaces those three bytes with LCALL D2B8. Its hook restores that displaced instruction before returning to CC03.

CC00: LCALL D2B8
      ; resume original code at CC03

D2B8: if R7 == 1: write neutral procamp
      if R7 == 2: write stereo descriptor
      MOV DPTR, #DE0B
      RET

Pseudocode above summarizes E1 E2; it is not an assembly source file.

Interrupt and callback entries

CBD4 = 05 enables the normal hook at CC00 and IRQ hook at CC20. Upstream research describes timer-tick work, signal detection and video register/state programming in IRQ context. The local patch does not replace that handler.

Upstream CC10 callback code calls ROM 6345 using a CODE-space table pointer. This is generic USB setup/control handling; the reviewed ROM also has an interface-2 AudioControl-like request route, but that route does not process PCM samples. Other helper and table locations depend on the EEPROM variant. An address such as D212 is inside the overlay, even when an upstream header calls it a “ROM function.”

Preserve executable entries used by mask ROM: uninitialized overlay bytes do not provide fallback ROM code. E5 E7

Audio-control requests versus the PCM producer path

The saved mask-ROM disassembly contains a USB EP0 class-request table at 2B34–2B8E. The SET_CUR request (01) follows 2B64 → 6096 → 5EB4; for interface number 2 and selector 1, the handler receives a byte into RAM staging C020 and writes it to XDATA F1F8. The matching GET_CUR (81) follows 2B69 → 6A2C → 5FDE, reads F1F8, masks bit 0, and returns it through EP0.

SET_CUR  01: EP0 → C020 → F1F8
GET_CUR  81: F1F8 & 01 → EP0

The dispatch and byte-transfer behavior are verified in the saved ROM. Interface 2 is consistent with the UAC 1.0 descriptor; selector 1 is Feature Unit Mute Control under the USB Audio 1.0 specification (A.9–A.10), so interpreting F1F8 bit 0 as mute is a strong inference. This is an audio control request, not an audio callback on the PCM producer path: the reviewed handler does not access PCM payload or establish a first-sample boundary. E17 E18

Address spaces, memory map and boot

An address is meaningful only with its space. MOVC reads CODE, MOVX accesses XDATA, and direct SFR accesses reach core/peripheral registers. Internal RAM uses a separate access path. Thus SFR 90 and XDATA FE90 are unrelated addresses.

Boot and local patch call flow

  1. Reset enters mask ROM. CODE 0000 jumps to 4149. Upstream identifies EEPROM loading/reloading at ROM 5F19. E17 E5 E7
  2. EEPROM header and code are loaded. Header offset 0000–002F maps to XDATA CBD0–CBFF; code starts at EEPROM 0030 and executes at CODE CC00. The local builder validates length and both additive checksums. E4 E5 E1 E2
  3. ROM initializes procamp, then calls stage 1. The saved ROM sequence at 31F2 calls 4D54, then sets R7=01 at 31F5 and calls the hook dispatcher at 31F7. The added hook overwrites current RAM state and hardware with neutral values. E17 E1 E2
  4. Stage 2 applies the audio descriptor change. R7=02 changes C4C5 to two channels and C4C9–C4CB to 48,000. Saved post-reconnect evidence confirms that the host enumerated stereo 48 kHz. E1 E2 E3 E8
  5. Original dispatch and IRQ processing continue. Other stages pass through; stage 2 is also an upstream main-loop command. UVC requests can later change procamp current values. The untouched ROM GET_DEF handler can still supply the original defaults. E1 E2 E5 E7
EEPROM layout and checksums
00–01   magic = A5 5A
02–03   code_length (16-bit big-endian)
04      hook flags (this image: 05)
05–2F   configuration / strings / other fields
30…     code_length bytes → CODE/XDATA CC00
end     header_sum (16-bit big-endian)
end+2   code_sum   (16-bit big-endian)

end        = 0x30 + code_length
header_sum = sum(image[0x02:0x30]) & 0xFFFF
code_sum   = sum(image[0x30:end])  & 0xFFFF

The upstream boot example uses 1735 code bytes. This dongle originally uses 1716; the patched image uses 1804. Copying upstream helper addresses or image sizes without matching the variant would be incorrect.

Host correction for the measured macOS path

The project’s later tone test identified reversed channels and a relative one-sample offset. The recorded correction is L[n] = raw_R[n], R[n] = raw_L[n+1]. A causal version swaps channels and delays corrected left by one sample:

pan=stereo|c0=c1|c1=c0,adelay=1S|0S

At 48 kHz, one sample is about 20.83 μs. This filter is documented for the measured uncorrected host path, not installed by the EEPROM patch. Do not apply it again to a stream whose driver already corrects the initial word. E1 E16
